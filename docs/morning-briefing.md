# Morning briefing

`scripts/morning-briefing/` runs inbox intake, extracts carryover from recent Obsidian daily notes, runs schedule, communications, work, and documents gather agents concurrently through `codex exec`, schema-checks and persists their results and JSONL events under `~/.local/state/morning-briefing/`, synthesizes one canonical Markdown briefing, atomically saves it to the daily note, waits for Obsidian Sync, then opens T3 Code and starts a fresh thread in this project with the T3 CLI (`t3 thread start`), on the model of `MORNING_BRIEFING_THREAD_ROLE`, the `writer` role. Its first message is `scripts/morning-briefing/prompts/morning-presentation.prompt.md` with the date and daily note path filled in. The thread renames and pins itself, unpins older briefing threads, repeats the saved briefing exactly, then on weekdays holds Herb to posting his Slack standup (and on Fridays his weekly update in the staff meeting notes) and then to making one phone call from the `phone` context of his task list, clears his Mac desktop and recent document photos every day, all before anything else, and then queues one task-review of the Inbox followed by bookmark-review in that same pinned thread. The CLI needs the T3 server running, so the publisher retries for about five minutes after opening the app. The mini's `Morning briefing` task runs it at 07:00.

Since 2026-11-28 the `writer` role's model, Gemini 4 Neon, owns the whole morning conversation (Herb decided), through T3's `antigravity` provider instance. That instance needs the Antigravity ACP runtime installed in T3's provider settings; the `agy` CLI that `llm run` uses is a separate install. `T3_PROVIDER_INSTANCES` maps each `llm` harness to its T3 instance. The CLI can't set effort, so the thread runs at the provider's default. The morning thread used to come from a T3 webhook task, but a task runs on the model of the thread that created it, Antigravity can't create one (it drops T3 tools whose schemas use union types, including `schedule_task`), and T3 refuses a model change while a turn is running, so a thread can't switch itself on its first turn. The gather and synthesis agents are separate. Gather agents run on `MORNING_BRIEFING_ROLE`, which must be a Codex role. Synthesis runs on `MORNING_BRIEFING_SYNTHESIS_ROLE`, the `writer` role, through `llm run`; it gets the carryover and merged artifacts in its prompt and no tools, so any harness works. Since 2026-11-26 that role is Gemini 4 Neon through Antigravity, as a trial of its prose.

## Running it

`pnpm briefing:morning` runs both briefings locally for the current date in the machine's time zone. An optional `YYYY-MM-DD` argument backfills another date, and `--dry-run` prints the time zone, planned lanes, destinations, and artifact paths without contacting sources or writing any destination. News runs from the repository directory even when the scheduler starts elsewhere. Each briefing finishes and presents independently; the command waits for both and reports any failures.

The workflow extracts carryover from the three latest daily briefings. Carryover is for checking what changed, not for repeating: Open issues lists an earlier item again only when it has a new development or needs Herb to act. It then reads the three latest prior `Morning briefing – YYYY-MM-DD` threads through the `t3` CLI. A read-only Codex agent summarizes each one in parallel: what Herb resolved, decided or updated, and what he asked for that wasn’t confirmed done. The summaries are added to the end of the carryover artifact, and the gather and synthesis agents treat Herb’s words there as more current than what the sources still show. That way he only has to tell Leo once. If T3 or a summary fails, the carryover records why and the briefing continues. Transcripts and summaries are kept in the run’s `session-review/` directory.

Next, the workflow runs these ephemeral Codex agents in parallel:

- schedule and the Tasks board;
- Gmail and messaging; and
- GitHub, meeting transcripts, and local agent sessions.

The schedule agent uses `pnpm --silent briefing:location` for last-known place context. The command reads Backtrack's iCloud CSV and compares its final row with approximate boxes for Barcelona (latitude 41.32–41.48, longitude 2.05–2.23) and Tamariu (latitude 41.90–41.93, longitude 3.19–3.23). It returns `other` outside both boxes. It does not interpret timestamps or apply an age cutoff. A missing or invalid file causes the command to fail; the briefing continues without location context. An optional file-path argument lets you read another Backtrack CSV.

Each agent writes schema-constrained JSON plus its complete JSONL event stream. One final agent, on the `writer` role, gets the merged results in its prompt and creates a validated canonical `final.md`. The publisher atomically writes that exact briefing under `## Daily briefing` in `~/Code/herbcaudill/notes/daily/YYYY-MM-DD.md`, waits for Obsidian Sync, then starts the morning thread. The news branch posts the saved JSON path to a T3 news webhook task. Each creates and pins its own dated thread and unpins only older threads of the same kind. The morning thread alone begins the Inbox review. The news webhook credential lives in `~/.config/morning-briefing/news-t3-webhook-url`; the news presentation prompt is versioned in `scripts/morning-briefing/prompts/news-presentation.prompt.md`.

Private artifacts never enter Git. Each run has its own directory under `~/.local/state/morning-briefing/YYYY-MM-DD/`, including `carryover.md`, per-lane results and event logs, `merged.json`, synthesis attempts, `final.md`, the presentation event log, and `manifest.json`. A single-run lock prevents scheduled runs from overlapping.

Task capture, research publication and duplicate detection use the managed Tasks CLI. See [Tasks integration](tasks-integration.md) for the enrolled-space binding and journal recovery.

## Scan filing

The `documents` lane files new family scans in Google Drive with the `file-scans` skill from dotfiles, which owns the naming rules and filing script, then reports scans that need Herb's attention. See `plans/005-scan-filing.md`.

## GitHub notifications

The `work` lane marks GitHub notifications done when they need no input from Herb, such as closed or merged subjects and bot activity. It leaves the rest in the inbox and reports them so synthesis can turn them into tasks. It takes no other GitHub action.

## Desktop and document photo cleanup

Herb's Mac desktop and the photos he takes of paperwork act as an illegible task list, so the morning thread clears both every day before the Inbox review. The thread runs on the mini and reaches the Mac with `ssh mac`, which is awake whenever Herb is reviewing. `scripts/mac-sources/morningCleanup.ts snapshot` lists the desktop and the photos from the last 30 days whose Photos text recognition found real text (at least 2 KB of it, which skips signs and labels; screenshots, hidden and trashed photos are excluded) and that have no recorded decision. It writes a viewable JPEG of each to `~/.local/state/leo/morning-cleanup/photos/` on the Mac, using the original when it's downloaded and Photos' largest local preview when it's only in iCloud. The thread copies those to the mini to look at and show Herb.

After Herb decides, the thread copies a JSON list of actions to the Mac and runs `morningCleanup.ts apply` on it. Desktop items go to the Trash or move to a folder; photos are copied to a folder; nothing is overwritten or deleted outright, and nothing is ever removed from Photos. Photo decisions are kept in `~/.local/state/leo/morning-cleanup/photo-decisions.json` on the Mac so a handled photo doesn't come back. Tasks are created through the tasks skill on the mini. Run both commands with `ssh -n mac node …`, not through `zsh -lc "…"` or `pnpm`: Windows PowerShell mangles nested quotes, and pnpm prints extra lines into the JSON.
